# DarcyWarp 3D audit and corrections — 2 November 2026

Audited development baseline: `f02f4d91ba70e681628c7ea43dbf004a5ccf997c`.
Changes are isolated on `fix/3d-audit-20261102`, targeting `dev`, not `main`.
The audit distinguishes legacy Cartesian, pinned MF6 6.6.2 Cartesian/layered
NPF, and experimental transformed terrain. It does not change governing
conductance, saturation, storage, contact or Newton/Picard equations, and does
not relax numerical acceptance thresholds.

## Confirmed defects and repairs

| Severity | Defect | Repair and regression |
| --- | --- | --- |
| High | CPU `numpy()` results alias the reusable fast 3D workspace. A later solve changes previously returned heads, corrupting retained histories and caller-side storage accounting. The existing confined transient MF6 test reports a 0.1087398902 m3/day independent cell imbalance. | Return owned snapshots at both ordinary and all-prescribed exits. Tests retain old results through a changed-boundary solve. The existing four-period MF6 comparison passes after this change. |
| High | Dimensional residual squaring underflows or overflows. Infinite gross throughput can yield a zero normalised imbalance, allowing a failed budget through the alternative acceptance branch. | Scaled RMS, finite physical fields/diagonals and aggregate checks, and validated tolerances. Both host and device-terrain terminal acceptance use the common gate. Tests reproduce representable 1e-200/1e200 residuals and overflowed opposing boundary throughput. |
| High | Failed Cartesian/terrain rebuilds close the prior usable session, and can change geometry/K metadata before replacement validation finishes. | Construct and validate the replacement before closing/installing it. Tests check retained session, workspace, geometry, conductivity and solvability after rejected replacements. |
| Medium | Fractional or overflowing mask values are cast to int32 before binary validation; fractional/boolean grid dimensions are silently truncated. | Validate original dimensions and masks before conversion. Cartesian public builders, direct sessions and terrain boundary masks have regression coverage. |
| Medium | Direct sessions created from integer arrays truncate fractional RHS/head updates; narrowing updates can overflow after validation. | Owned floating fields and validation in the destination dtype before mutation. Face updates validate all replacements before assignment. |
| Medium | Arbitrary face updates retain unrelated original cell-centred K, which a later unconfined solve silently reuses. | Invalidate K provenance after raw face updates. Unconfined calls must rebuild from K or supply explicit K arrays. |
| Medium | Clearing a layered NPF initial guess passes `None` into the reference case although Cartesian mode supplies zero. | Resolve a new zero guess consistently for both geometries; a layered public solve verifies it. |
| Medium | Negative storage diagonals in the Cartesian diagnostic are silently clipped to zero. | Reject invalid storage rather than validate a different budget. |
| Medium | Terrain input accepts competing geometry specifications and empty horizontal dimensions. | Reject ambiguous inputs and empty grids explicitly. |
| Test infrastructure | Some parametrized CUDA tests, and a test with an internal CPU/CUDA loop, fail rather than report unavailable GPU coverage. | Explicit CUDA-unavailable skips; parameterize the internal loop so its CPU/native comparison still executes. No CPU test is relabelled as GPU validation. |
| Reference portability | Live NPF tests accept only one historical local MF6 executable hash, blocking the official release of the same exact version. | Retain that historical hash and add the measured official Linux 6.6.2 hash. Both version and SHA256 remain mandatory. Record build identity with each native result; reject unknown builds and other versions. |

## Reproducible execution

Canonical CI uses Python 3.12, Warp 1.17.0, FloPy 3.9.5 and the official Linux
MODFLOW 6.6.2 executable. The local audit execution used Python 3.13.5,
NumPy 2.3.5, SciPy 1.17.0 and Warp 1.17.0 on CPU. No fresh CUDA execution or
GPU performance claim is made. CI uploads exact dependency versions, commit,
source hashes, executable checksum, JUnit results and logs separately for
`core`, `physics`, `npf`, `terrain`, and `2d-regression` groups.

```bash
export DARCY_FLOAT=float64
export PYTHONPATH=.:working_tests
export OPENBLAS_NUM_THREADS=1
export OMP_NUM_THREADS=1
python -m pip install pytest pytest-timeout
python working_tests/run_3d_audit.py
```

Set `DARCYWARP_AUDIT_GROUP` to run one named group. The 600 s per-test timeout
is an execution budget, not a changed solver iteration limit or convergence
tolerance. CUDA checks remain skipped, not passed, on a CPU-only machine.

The untouched numerical baseline was tested in a clean GitHub checkout at
`0f351eac5d5b6970909213d1b6af8f7e1b433dc8` (workflow-only commit):
**1,300 passed, 43 failed, 3 setup errors, 444 skipped**. Run:

## A genuine runnable 3D example

```bash
DARCY_FLOAT=float64 python -m examples.layered_confined_3d
```

This synthetic 9 x 4 x 5 grid has nine uniform-thickness Cartesian layers with
contrasting conductivity, fixed heads at the top/bottom cell centres, and
impermeable lateral faces. Units are metres and days. An independent half-cell
series-resistance calculation supplies the exact heads and vertical face flow.
The script saves actual input/result arrays and JSON diagnostics; no external
model data, plotting package, MODFLOW or GPU is required.

The local CPU run converged in 12 cycles, with maximum head error
`3.730349362740526e-12 m`, maximum face-flow error
`1.7271304386667907e-9 m3/day`, and relative cell imbalance
`5.66855740122958e-12`. This checks a deliberately simple problem, not general
site-model accuracy or terrain branch selection.

## Remaining boundaries and release decision

- The NPF formulation is a **steady** pinned-law implementation. Do not advertise
  legacy/terrain transient storage as NPF transient support.
- Terrain remains experimental: historical independent comparisons show branch
  sensitivity and constitutive/discretisation differences from MF6. These
  findings are not repaired by changing a stopping tolerance or choosing a
  solution that looks closer to MF6.
- CPU/GPU agreement, graph capture/replay, GPU memory stability and performance
  require a fresh run on actual CUDA hardware before a GPU release promotion.
- The historical river-loss runner imports missing `case_studies` modules. It
  cannot run from this checkout. Documentation now states that explicitly and
  points to the working synthetic example; the missing original study was not
  invented or replaced with an alleged equivalent.
- Development documentation contains historical snapshots with superseded claims.
  This report and current entry-point contracts govern the audited scope; the
  refreshed `main` presentation/ownership/citation material must be retained
  during any later integration. Only touched source licence headers are aligned
  here; the Apache-licensed Warp-derived GMRES notice remains intact.

These fixes strengthen the case for a scoped 3D release candidate. They do not
certify the full development branch, turn skipped CUDA tests into passes, or
justify a wholesale `dev` merge into the public 2D release.
